# CRM 业务分析平台部署与基础运维说明

本文面向需要安装、更新、备份或排查平台的运维人员。平台是一个运行在 Docker Compose 中的 Node.js 应用，公开访问路径固定为 \`/crm/\`，应用容器默认只绑定服务器本机的 \`127.0.0.1:3100\`，外部访问由 Nginx 或其他反向代理负责。

## 一、部署前需要准备什么

### 服务器

- 64 位 Linux 服务器，能够运行 Docker 和 Docker Compose。
- 服务器本机端口 \`3100\` 可用；该端口不需要开放到公网。
- 如果与其他网站共用服务器，需要已有 Nginx/Caddy 反向代理能力。
- 生产访问必须配置 HTTPS。只有 IP 也可以使用受控证书方案，但浏览器必须信任证书。

### 凭据和配置

需要准备三项配置：

| 配置 | 用途 | 注意事项 |
| --- | --- | --- |
| \`CRM_ADMIN_USERNAME\` | 当前唯一管理员账号名 | 不是角色系统，不能创建普通操作员 |
| \`CRM_ADMIN_PASSWORD_HASH\` | 管理员密码的 scrypt 摘要 | 不写明文密码，不提交 Git |
| \`CRM_SESSION_SECRET\` | 签名登录会话 | 至少 32 字节，轮换后全部旧会话失效 |

密码摘要在可信开发机上生成：

\`\`\`bash
cd platform
read -s -p 'CRM admin password: ' CRM_PASSWORD; echo
printf '%s' "$CRM_PASSWORD" | npm run admin:hash -- --stdin
unset CRM_PASSWORD
\`\`\`

会话密钥可以使用：

\`\`\`bash
openssl rand -base64 48
\`\`\`

不要把以上真实输出复制到仓库、工单、聊天或本文档。

## 二、首次部署

### 1. 获取项目文件

\`\`\`bash
sudo install -d -o dev03 -g dev03 /opt/crm-settlement
git clone https://github.com/hydintern3/crm-settlement.git /opt/crm-settlement
cd /opt/crm-settlement
\`\`\`

如果项目已存在，更新前先确认工作树没有服务器本地修改：

\`\`\`bash
cd /opt/crm-settlement
git status --short
git pull --ff-only
git log -1 --oneline
\`\`\`

### 2. 创建环境配置

\`\`\`bash
cd /opt/crm-settlement
cp -n .env.deploy.example .env
\`\`\`

\`.env\` 至少应包含以下结构，示例值必须替换：

\`\`\`dotenv
BIND_ADDRESS=127.0.0.1
APP_PORT=3100
CRM_IMAGE=ghcr.io/hydintern3/crm-settlement:latest
CRM_ADMIN_USERNAME=admin
CRM_ADMIN_PASSWORD_HASH='scrypt$...'
CRM_SESSION_SECRET=至少32字节随机值
\`\`\`

权限应限制为只有运维账号可读：

\`\`\`bash
sudo chmod 600 /opt/crm-settlement/.env
\`\`\`

### 3. 获取镜像并启动

有网络时：

\`\`\`bash
cd /opt/crm-settlement
sudo docker compose pull crm-platform
sudo docker compose config --quiet
sudo docker compose up -d --no-build
sudo docker compose ps
curl --fail http://127.0.0.1:3100/crm/api/health
\`\`\`

健康检查预期返回：

\`\`\`json
{"status":"ok","service":"crm-analysis-platform"}
\`\`\`

### 4. 配置 Nginx

将仓库中的 \`deploy/nginx/crm-location.conf\` 安装到 Nginx 片段目录，并在现有 \`server {}\` 中 include：

\`\`\`bash
sudo install -d -m 755 /etc/nginx/snippets
sudo install -m 644 /opt/crm-settlement/deploy/nginx/crm-location.conf /etc/nginx/snippets/crm-location.conf
sudo nano /etc/nginx/sites-enabled/<实际站点配置>
\`\`\`

在站点的 \`server {}\` 内加入：

\`\`\`nginx
include /etc/nginx/snippets/crm-location.conf;
\`\`\`

其中最重要的是两条路由：\`/crm/assets/\` 必须代理到应用的 \`/assets/\`，\`/crm/\` 必须设置 \`client_max_body_size 110m\` 并代理到 \`127.0.0.1:3100\`。修改后检查并重载：

\`\`\`bash
sudo nginx -t
sudo systemctl reload nginx
curl --fail http://127.0.0.1/crm/api/health
\`\`\`

不要删除同一站点原来转发其他项目的 \`location /\`。

## 三、离线镜像更新

云主机无法访问 GHCR 时，从 GitHub Actions 下载同一构建产物中的：

- \`crm-settlement-linux-amd64.tar.gz\`
- \`crm-settlement-linux-amd64.tar.gz.sha256\`

上传到服务器：

\`\`\`powershell
scp crm-settlement-linux-amd64.tar.gz \`
  crm-settlement-linux-amd64.tar.gz.sha256 \`
  dev03@<服务器IP>:/home/dev03/
\`\`\`

在服务器执行：

\`\`\`bash
sudo bash /opt/crm-settlement/deploy/offline-deploy.sh \
  /home/dev03/crm-settlement-linux-amd64.tar.gz
\`\`\`

脚本会依次完成：校验 SHA256、加载镜像、把 \`.env\` 的 \`CRM_IMAGE\` 统一为 \`latest\`、使用 \`--pull never --force-recreate\` 重建容器、等待健康检查。它不会删除 Docker 数据卷，也不会修改管理员账号、密码摘要、会话密钥等其他环境变量。

离线包只保证带 \`latest\` 标签。不要在隔离网络环境中直接运行会访问 GHCR 的 \`docker compose pull\`。

## 四、日常更新

联网更新：

\`\`\`bash
cd /opt/crm-settlement
git status --short
git pull --ff-only
sudo docker compose pull crm-platform
sudo docker compose up -d --no-build
sudo docker compose ps
curl --fail http://127.0.0.1:3100/crm/api/health
curl --fail http://127.0.0.1/crm/api/health
\`\`\`

每次更新后都要确认：

- 容器状态为 running；
- 本机和 Nginx 两个健康检查都成功；
- 浏览器能打开 \`/crm/\` 并完成登录；
- 数据中心仍能看到原来的数据版本；
- 图表模板仍然存在。

如果仓库更新了 Nginx 片段，还要重新安装片段并重载 Nginx；只更新 Git 文件不会改变服务器当前生效配置。

## 五、查看日志和处理故障

查看容器状态和最近日志：

\`\`\`bash
cd /opt/crm-settlement
sudo docker compose ps
sudo docker compose logs --tail=200 crm-platform
\`\`\`

按现象排查：

| 现象 | 先检查 |
| --- | --- |
| 健康检查失败 | \`docker compose logs\`、\`.env\` 三项必填配置、容器是否反复重启 |
| 浏览器打不开页面 | Nginx \`nginx -t\`、\`/crm/assets/\` 路由、端口 3100 是否监听 |
| 登录后回登录页 | HTTPS、\`Secure\` Cookie、Nginx 的 \`X-Forwarded-Proto\` |
| 上传 413 | 新镜像是否已部署、Nginx 是否实际有 \`client_max_body_size 110m\` |
| 数据突然为空 | 数据卷是否仍挂载、数据中心是否切换到了空或不可用版本 |
| 图表模板消失 | \`CRM_DATA_DIR/dashboard\` 是否在持久化卷内，是否误用了 \`down -v\` |

查看 Nginx 实际生效配置：

\`\`\`bash
sudo nginx -T | grep -n -A3 -B2 'client_max_body_size 110m'
\`\`\`

## 六、备份与恢复

业务版本、上传原文件、快照、版本清单、图表模板和审计日志都在 Docker 命名卷 \`crm-data\` 中。查看卷位置：

\`\`\`bash
sudo docker volume inspect crm-settlement_crm-data
\`\`\`

备份建议：

1. 选择业务低峰期，暂停上传和版本切换。
2. 停止应用容器或至少确保没有写入。
3. 备份 \`crm-data\` 卷内容到受控的备份介质。
4. 记录备份时间、镜像版本和当前激活版本。
5. 验证备份文件可读，不把它放到公开 Web 目录。

恢复前先停止应用，恢复后再启动并检查健康状态。不要执行 \`docker compose down -v\`，因为 \`-v\` 会删除持久化卷。镜像回滚和业务数据回滚是两件事：镜像通过 Compose 标签回滚，数据版本通过平台“数据中心”激活历史版本。

## 七、按提交版本回滚

联网环境可以把 \`.env\` 的 \`CRM_IMAGE\` 临时改为已知正常的提交 SHA 标签：

\`\`\`dotenv
CRM_IMAGE=ghcr.io/hydintern3/crm-settlement:<完整提交SHA>
\`\`\`

然后：

\`\`\`bash
sudo docker compose pull crm-platform
sudo docker compose up -d --no-build
curl --fail http://127.0.0.1:3100/crm/api/health
\`\`\`

回滚后记录原因和镜像标签。离线环境必须加载带有对应标签的历史镜像包，不要假设每个离线包都带 SHA 标签。

## 八、重新发布前的安全检查

- 生产镜像不应包含 \`platform/public/data/local-snapshot.json\`、CSV 或 Excel 文件。
- \`.env\` 不应进入 Git。
- 数据卷必须备份，升级和重建不能删除它。
- 应用不要直接暴露到公网；保持 \`BIND_ADDRESS=127.0.0.1\`，由 HTTPS 反向代理对外服务。
- 生产环境不在服务器上执行 \`npm install\` 或本地构建，使用 CI 生成的已验证镜像。
