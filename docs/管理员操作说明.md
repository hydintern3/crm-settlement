# CRM 业务分析平台管理员操作说明

本文面向日常使用平台的管理员、财务人员和业务负责人。文中的“管理员”是当前系统唯一的登录角色。当前版本没有超级管理员、普通操作员或按功能分权；所有能够登录的账号都拥有同样的管理能力。

## 一、先了解平台能做什么

平台用于把 CRM 导出的业务表格放入一个可查询、可筛选、可复核的工作台。主要功能包括：

- 导入 CSV、XLS、XLSX、XLSM、XLSB、ODS 文件，并选择其中的业务表和服务商表。
- 保存多个数据版本，手动选择当前使用的版本。
- 选择多个业务工作表进行汇总，并按“设备编号”去重整合。
- 查看总览、统一查询、业务分析、销售分析、供应商分析、服务商分析、毛利与目标、结算中心和数据中心。
- 使用年份、月份、负责人、业务属性、活跃状态、计量规则等筛选条件联动查看指标、图表和明细。
- 导出当前筛选结果为 UTF-8 BOM CSV。
- 创建、编辑、复制、固定、排序、归档和恢复总览图表模板。

平台不会修改原始 Excel，不会回写 BH 公式，也不会因为缺少结算字段而把业务记录从查询中删除。缺少数据通常显示为 \`--\`；真实数字 0 会显示为 0。

## 二、登录与账号边界

### 登录

1. 在浏览器打开平台地址，通常为 \`https://服务器地址/crm/\`。
2. 输入部署时配置的管理员账号和密码。
3. 登录成功后进入总览；如果尚未发布数据，页面会显示等待导入数据的空状态。

登录会话默认持续 8 小时。生产环境使用安全 Cookie，因此必须通过 HTTPS 访问；如果只用 HTTP，可能出现登录后又回到登录页的现象。

### 当前账号限制

- 账号由服务器环境变量 \`CRM_ADMIN_USERNAME\` 配置。
- 密码只以 scrypt 摘要形式保存在服务器配置中，不能在平台页面查看原密码。
- 当前没有页面可以新增账号、停用账号、重置其他人的密码或设置角色。
- 不要多人长期共用一个账号；如果必须共用，应至少在交接表中约定谁在何时操作。后续若需要正式的“超级管理员/普通操作员”制度，应单独开发用户和角色系统，不能靠增加第二个固定环境变量替代。

## 三、首次使用：导入数据

### 导入前准备

1. 尽量使用从 CRM 导出的原始文件或由财务确认的脱敏副本。
2. 加密工作簿不要在平台中尝试破解。请在可信电脑中另存为未加密副本或导出 CSV，再导入平台。
3. 确认表格中的设备编号、初始完工日期、完工日期、业务属性、活跃状态和计量规则等字段没有被意外改名或删除。
4. 单次上传的所有原始文件合计不超过 100 MB。接近上限时拆成多个版本，之后在数据中心整合。

### 导入步骤

1. 点击右上角“导入数据”，或进入“数据中心”点击导入。
2. 选择一个或多个表格文件。
3. 等待平台识别工作表。平台会把工作表分成业务表、服务商表和未识别表。
4. 明确选择当前要使用的业务工作表。平台不会自动把“1期”和“2期”相加。
5. 如果确实需要汇总多个业务工作表，逐一勾选，并确认这些工作表可以按同一业务口径相加。
6. 选择服务商信息工作表（如果本次文件包含该表）。
7. 填写便于识别的版本名称，例如“2026-08-21 活跃业务导出”。不要把密码、令牌或客户敏感信息写入名称。
8. 确认预览内容和工作表数量后发布。

导入完成后，平台会显示输入行数、保留行数、重复设备数和空设备编号数。设备编号相同的记录只保留一条：较高期次优先；无法判断期次时，完工日期较新的优先。设备编号为空的记录不会互相合并，而会保留并进入质量检查。

### 导入后的检查

发布后先打开“数据中心”确认：

- 版本状态为可用，而不是不可用或字段映射失败；
- 业务记录数量大致符合原文件；
- 设备编号、业务名称、负责人、日期、活跃状态和计量规则没有整体显示为 \`--\`；
- 服务编号能够与服务商信息关联；
- 数据版本名称、发布时间和来源文件正确。

如果绝大多数字段都为空，优先检查是否选错了工作表。历史上 \`Sheet1\` 可能是汇总/透视表，业务明细通常在 \`Worksheet\`。表头前后空格现在会自动归一化，但旧的空字段版本不能自动修复，必须重新上传原始明细表。

## 四、数据中心：版本、整合和切换

### 查看版本

“数据中心”保存每次上传的原始文件、解析快照、版本清单和审计记录。历史版本不会因为切换当前版本而被覆盖。

### 激活一个版本

1. 在版本列表中找到要使用的版本。
2. 检查版本来源、行数、状态和是否为整合版本。
3. 点击“激活”并填写切换原因。
4. 切换后返回总览，确认更新时间和记录数已经变化。

激活只是改变“当前使用版本”的指针，不会修改历史文件。当前激活版本不能删除。

### 整合多个版本

1. 在数据中心选择多个原始业务版本。
2. 确认这些版本的字段含义一致，且确实需要合并。
3. 输入整合版本名称并提交。
4. 查看整合结果中的输入行数、保留行数、排除行数、重复设备数和空设备编号数。
5. 按需要激活新生成的整合版本。

整合按设备编号去重，并采用字段级覆盖：较新版本的非空字段覆盖旧字段，较新版本的普通空值不会擦掉旧值。整合版本生成后不可变；如果规则或源数据后来修正，要重新选择原始版本生成新的整合版本。

### 删除版本

只有不在使用中、且没有被整合版本引用的历史版本才可以删除。删除需要二次确认，服务端还会再次校验。删除后不能从平台回收，只能重新上传原始文件恢复，因此删除前先确认已经完成备份。

## 五、各页面怎么用

### 总览

总览显示当前筛选范围内的指标、年度复核和固定图表。图表会跟随当前数据版本和全局筛选实时重算。

- 点击图表中的计量规则、负责人、供应商或服务商，可以进入对应分析或查询页面。
- “2026 年度新增复核”使用初始完工日期判定新增总体，不受当前活跃状态等筛选排除。
- “当年新增当年拆机确认”使用初始完工日期和 CRM 完工日期的双日期口径。
- “年度净增长分析”的新增只取当前计量规则为“新增量”的记录；年度拆机只取业务属性为拆机且 CRM 完工日期在该年度的记录。

### 统一查询

这里用于查明细、分页和导出。搜索框可搜索业务、服务、拆机原因和已脱敏固话尾号等非敏感字段。点击筛选按钮可以多选；点击“全部”可清空该维度限制；长按约半秒可只保留当前选项。

导出前先确认页面上方的筛选条件。导出的 CSV 包含设备编号和已建模的非敏感核心字段，联系电话只输出脱敏结果。

### 业务分析、销售分析、供应商分析、服务商分析

这些页面分别按业务趋势、负责人、供应商和 I/II 服务编号查看聚合结果。供应商来自源表“供应商”字段，服务商按服务编号识别，两者不要混为一个概念。带有总计的表格底部会重新计算总体比率、均值和占比，不能把各行百分比直接相加。

### 毛利与目标

如果没有正式目标、完整毛利输入或确认口径，页面只显示缺失清单和 \`--\`。平台不生成模拟金额，也不把 CRM 业务毛利当成正式财务结算金额。

### 结算中心

结算中心是候选工作分流，不是正式付款单。缺少计量规则、月平均计量，或属于年付/两年付、拆机、变更及服务商状态异常的记录，会标记为“结算待复核”。年付、两年付拆机测算在没有稳定实际账单规律前必须人工确认。

### 自定义图表

在总览点击“新建图表”，按向导选择图表类型、维度、系列、指标、聚合方式、排序、Top N 和卡片尺寸。保存后可固定到总览。可以编辑、复制、调整顺序、取消固定、归档和恢复。

图表模板保存的是配置，不保存统计结果；统计结果始终由当前版本和筛选条件重新计算。模板和审计文件位于服务器持久化数据目录，升级容器时不能删除数据卷。

## 六、日常安全和审计要求

- 不在聊天、截图、日志、文档或 Git 中记录密码、密码摘要、会话密钥、令牌和真实客户信息。
- 不把 \`public/data/local-snapshot.json\` 或原始 Excel 提交到仓库或发布包。
- 不从空值、简称或历史记录推断已被清空或脱敏的字段。
- 不依据结算候选清单直接付款、更新 CRM 状态或发送正式结算单。
- 每次上传、切换、整合和模板修改都填写清楚原因，方便审计追溯。

## 七、常见问题

### 登录后反复回到登录页

检查是否使用 HTTPS、Nginx 是否正确转发 \`X-Forwarded-Proto\`，以及访问路径是否为 \`/crm/\`。生产 Cookie 带 \`Secure\` 标记，纯 HTTP 下浏览器不会发送它。

### 导入后全部或大部分字段为 \`--\`

检查是否选中了汇总/透视表而不是业务明细表；检查是否仍在使用历史空字段版本。重新选择正确的业务明细工作表并重新上传。

### 上传提示文件过大

平台原始文件合计上限是 100 MB，Nginx 外层上限是 110 MB。拆分文件后建立多个版本，再使用数据中心整合。

### 页面显示没有数据

这可能表示尚未发布版本、当前筛选条件没有匹配项，或数据版本不可用。先进入数据中心确认版本状态，再点击“重置筛选”。

### 结算金额显示 \`--\`

这通常是设计结果，不是计算故障。检查记录是否缺少月平均计量、计量规则，或属于年付/两年付等必须人工复核场景。
